# FreeLP requirements audit

Audit date: 2026-09-10. Scope is the complete private, deployment-ready FreeLP application and separate contracts PR. Public launch and production-chain transactions are intentionally not performed. See the validation record for test evidence and the launch checklist for later publication steps.

| Requirement | Current implementation and evidence |
| --- | --- |
| Private new interface repository | `moodysalem/freelp` is private; its releases and CI are private. Private workflow paths use an offline IPFS node and private GitHub issuance evidence, without public transparency logging. |
| Reduced fork, one initial commit, MIT | Exactly one root commit, `6bde9e7b664540bdc190908281d1f5b1c7a3a2ca`; later commits are FreeLP development. New code is MIT. Retained contract/dependency/Bun notices remain separate. `notices:check` reproduces 158 package notices. |
| New Solidity remains in EVM contracts PR | PR #372 is open with head `577c33f8df83c7af7dcd3d3d17fbf867710f0f29`. The six-file diff adds only FreeLP contract, packed types, metadata, tests, gas snapshot, and documentation. Complexity tooling is absent. |
| EVM only; no Starknet | Source, package, lockfile, asset, and workflow inspection shows no Starknet code or dependencies. Imported artifacts target Solidity 0.8.33 / Osaka, as pinned in `artifacts/source.json`. Compatible EVM execution is required. |
| Only LP management | App routes are positions, create, settings, deployment, terms, and build provenance. No swaps/orders, routing APIs, rewards, rankings, USD/APR, charts, bridges, or history UI. Existing Core swap capability is not exposed by the app. |
| RPC-only runtime, free and replaceable RPC | `src/rpc.ts` uses the configured HTTP RPC with CCIP reads disabled. Default RPC requires no key; Settings accepts a replacement/self-hosted node. Browser tests forbid nonlocal services and historical logs. No hosted wallet connector, analytics, fonts, token API, or metadata service. |
| No recurring project application service | Static files, configured RPC, and injected wallet suffice. CI seeds public IPFS directly after launch; no pin API/project server is required. CARs and verified local caches are independently retainable. Gas, chain operation, and somebody retaining bytes are real dependencies, not promised free resources. |
| Authoritative data on-chain | Manager stores immutable pool/range descriptors and ERC721 ownership/enumeration. Principal, fees, pool state, prices, and token information come from chain reads. Local settings and consent are preferences; deleting browser history does not lose positions. |
| Fully on-chain NFT metadata | `FreeLPMetadata.sol` returns base64 JSON containing base64 monochrome SVG. Only bounded on-chain numeric/address fields are rendered, with no external token metadata or image reads. Contract tests decode metadata. |
| Ownerless zero-fee manager | FreeLP has immutable Core/accountant bindings, no owner/admin/upgrade/metadata setter, and no manager fee. Runtime checks compare exact bundled code and all immutable references before transactions. |
| ERC721 standards and efficient storage | Enumerable and Metadata interfaces are supported. `uint64` monotonic IDs pack four per owner/global array word. Custom packed descriptor types use three descriptor/index slots per NFT. Indexed lookup and mutation are constant-time; linked-list tradeoffs are documented. Exhaustion, packing boundaries, and transfer/burn invariants are tested. |
| Complete listing, sorting, no UI pagination | `positions()` reads all standard owner indexes, sorts IDs, and fetches every descriptor/amount/metadata record at one block in bounded RPC batches. Unit coverage includes 257 positions; browser reload rediscovers real minted NFTs without logs. |
| Create and initialize positions | Local-chain browser tests deploy the real bundled Core/manager and create real concentrated positions. Price, raw tick, and full-range inputs use validated pool configuration and on-chain integer quotes. Existing pool initialization state overrides irrelevant initial-price input. |
| Add, collect, partial/full withdrawal, transfer, burn | Full browser lifecycles cover ordinary ERC20s, missing token decimals, and native ETH. They use real approval/reset transactions, add liquidity, transfer out/back, collect, withdraw partially/fully, and burn. Native flow leaves no ETH stranded in the manager. Contract settlement/refund/reentrancy tests pass. |
| Permissionless deployment page and recovery | Deploy can use existing Core or create Core then manager. Confirmed addresses are saved before subsequent verification reads; failed reads do not lose deployments. Browser tests fail both verification stages, reload, verify, and complete LP management without redeployment. |
| Terms before every transaction | Explicit unchecked acceptance is versioned per account; shared transaction entrypoint rechecks it, wallet account, and wallet chain before submission. Tests cover no requests before consent, account change during gas estimation, stale/cleared/unavailable storage, checkbox reset, and disabled deployment before acceptance. |
| Chain/RPC/configuration recovery | RPC failure and chain mismatch are reported. Replacement settings survive reload. Malformed saved/imported settings cannot crash rendering. Wallet account/chain events clear the active account and require reconnecting. |
| Plain black and white, no branding/assets | System fonts, monochrome CSS, ordinary borders and explicit states; no logo/image assets or marketing routes. NFT SVG is monochrome. Required licenses and protocol/repository identifiers remain. UI visual check and browser gateway checks are recorded. |
| Static IPFS deployment per main/tag commit | Relative Vite assets and hash routes work under path and subdomain gateways. CI packages deterministic inner site and outer proof CARs, verifies them using isolated Kubo, and retains per-commit releases. Public seeding uses a fresh node so private blockstores are never exposed. |
| Independent repository-specific build trust | CLI pins exact repository/owner numeric IDs, workflow, refs, source commit, and independent trust roots. Private signed issuance binds the descriptor digest; public Sigstore verification is a separate policy. Descriptor authenticates file hashes, site CID, and launcher hashes; outer CID binds proof and site. Candidate bytes cannot replace verifier roots. |
| Latest-release launcher, offline operation, browser ordering | Authentic private `v0.0.1` was discovered as latest, selected explicitly, and reverified offline using an independently authenticated binary. Wrong repository/workflow/proof/content/CIDs are rejected. Integration checks cover wrong commit/tag, unavailable discovery, interrupted download, rollback, browser ordering, and port conflict without replacing an existing app. |
| Build/test gates | App lint, typecheck, 20 unit tests, production build, and six browser tests pass locally. Contract PR full CI passed 980 tests with gas-snapshot checking. Final private release CI repeats app/browser/gateway/bootstrap/license checks; its artifacts must be authenticated before handoff. |

## Publication boundary

Public Sigstore issuance and real public DHT seeding are implemented and gated on repository visibility. Private signed provenance, byte verification, deterministic packaging, offline IPFS, and gateway execution are tested now. Public issuance/seeding must pass on the first authorized public release before announcement; exposing private source or CIDs to run those checks now would violate the privacy requirement. This is a later launch action, not a missing backend or paid service requirement.

Production deployments and independent external contract review are not claimed by this audit. The ownerless contracts and interface are deployable without a project key or service, but neither build provenance nor tests establish freedom from defects.
