# FreeLP implementation and verification

FreeLP uses injected wallets and RPC endpoints only. The initial 11 mainnets match the official interface's EVM list; other viem mainnets can be enabled in Settings. Names, native-token metadata and default endpoints come from viem. RPC overrides are empty by default. Disabled chains stay disabled, including when all chains are off. Native currencies use the zero address, and imported metadata is unique by chain ID and normalized token address.

Creation checks for code at Core, FreeLP and FreeLPDataFetcher, then scopes token selection and balances to the selected network. Pool-key changes load one pool through the data fetcher. The Advanced switch hides the fee cards and exposes fee, type, spacing and extension editors. Liquidity and selected range share one section, with paired token bars, exact hover amounts, drag selection, zoom and centered spacing presets. Initial price appears only for a new pool. Numeric URL parameters snap for display without rewriting the incoming URL.

Pinned @ekubo/sdk math calculates deposit amounts locally. `evmLiquidity.ts` accounts for the EVM's intermediate flooring and the published SDK's token0 rounding issue; browser tests compare the results to FreeLP's integer quotes. Amount changes do not request contract quotes. Balances and allowances are read through FreeLPDataFetcher and refreshed after transactions. Wallets supporting EIP-5792 can submit approval resets, approvals and deposits together, without requiring atomic execution. Sequential batch simulation precedes submission, and partial/pending batches are never automatically resubmitted. Separate approval buttons remain available. Withdrawals and fee collection use a manager multicall.

The fixed addresses are Core `0x00000000000014aA86C5d3c41765bb24e11bd701`, FreeLP `0xF45a36e4FFbeaEBdCE8cc574f52039aeC6b468A1`, and FreeLPDataFetcher `0x753E7461313B6C9A4F0D6a2915271aBfb54fB071`. The Deploy page prepares their deterministic CREATE2 deployments. Transaction simulation, wallet/account checks and receipt validation remain mandatory. Terms are informational and have no acceptance gate.

Validation covers SDK/contract parity, standard and batched ERC20 lifecycles, native-token positions, stableswap, collection, withdrawal with automatic NFT burning, URL handling, chain settings, token import and balance caching. Production checks also run Axe at mobile/desktop sizes, Lighthouse thresholds, and the packaged bunx/npx launcher. All routes and transaction code ship in one JavaScript bundle, so navigation needs no additional code fetches from IPFS. Reports are retained in CI.

The npm package is public. Launch with `bunx @ekubo/freelp@latest` or `npx @ekubo/freelp@latest`. CI publishes immutable IPFS previews and attaches their links to commits. IPFS information is kept out of the application itself.
